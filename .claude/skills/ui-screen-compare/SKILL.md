# 실제 화면 Before/After 리포트

UI 피드백은 위치·간격·줄바꿈이 맞아야 쓸 수 있다. 손으로 그린 목업은 조금씩 달라 쓰지 않는다(사용자 결정 2026-10-28). 이 스킬은 **구현 → 실제 화면 캡처 → 원본 CSS 대조 → 게시 → 정리**를 한 번에 한다. 오래 걸려도 이 방식으로 한다.

도구와 명령은 `scripts/dev/screen-report/README.md`에 있다. 이 문서는 순서와 판단 기준만 적는다. 시작 전에 README를 읽는다.

## 0. 범위 정하기

- 무엇을 비교하는지 정한다: 어떤 화면, 어떤 학생 상태(케이스), 한국어/영어, 인쇄본 여부.
- 케이스는 **변화가 가장 크게 보이는 학생**과 **가장 흔한 학생**을 함께 고른다. 예: 편입·전과·이수유형 미정 같은 끝 케이스 + 체험단 다수(컴소공 2025, 공학3계열 2026)와 같은 일반 케이스.
- 사용자가 "아직 고치지 말라"고 했어도 시안 비교를 원하면 **시안 브랜치**에 구현한다. 작업 브랜치와 섞지 않고, 푸시·PR은 하지 않는다. 확정되면 그 브랜치를 그대로 이어서 본 작업을 한다.

## 1. 시안을 먼저 구현한다

- 기준 브랜치(지금 화면)에서 `git switch -c proto/<주제>`.
- 추천안을 코드로 구현한다. 화면 문구는 CLAUDE.md "화면 언어(i18n)" 규칙대로 ko·en을 같이 고친다.
- 관련 테스트를 돌려 깨지지 않게 한다(시안이어도 화면이 실제로 뜨는지가 중요하다).
- 구현할 수 없는 부분(서버 데이터·운영 반영이 필요한 것)은 화면 단계에서 흉내 내지 말고 리포트의 "시안에서 하지 않은 것"에 적는다. 화면 표시 단계에서 걷어 내는 식의 임시 처리를 했으면 그것도 적는다.

## 2. 두 화면을 같은 조건으로 띄운다

README "순서" 1~2를 따른다. 요점:

- 지금 화면 = 기준 브랜치를 `git worktree add ../wku-before-preview <브랜치>`로 꺼내 **루트 node_modules만 junction**으로 잇고 5174 포트로 띄운다. 바꾼 뒤 = 작업 트리(5173). 서버(3000)·로그인 쿠키·테스트 계정은 하나를 같이 쓴다.
- 서버를 고친 시안이면 서버는 작업 트리 것이 돈다. 지금 화면 쪽이 서버 변경의 영향을 받지 않는지 확인한다(새 필드 추가는 괜찮고, 기존 응답 값을 바꾸면 지금 화면도 달라진다).
- 서버는 Bash가 아니라 `preview_start`로 띄운다. `.claude/launch.json`에 `client-before`(5174)와 `screen-report`(3010, 인자로 작업 폴더) 항목을 **임시로** 넣고, 끝나면 `git checkout -- .claude/launch.json`으로 되돌린다.
- 작업 폴더는 세션 스크래치패드 아래(`screen-report/`)에 두고 폰트를 복사해 둔다.
- 두 탭 모두 `resize_window` 모바일(375×812)·라이트로 둔다.

## 3. 케이스 상태를 만들고 뜬다

- `test-state.js`와 `cases.json`으로 dev-login `/onboarded` 계정에 케이스를 넣는다(README "테스트 계정 상태 만들기"). 과목 이름은 실제 개설 과목에서 고른다.
- 케이스마다: 상태 적용 → 두 탭 새로 고침 → `history.pushState`/`popstate`로 화면 이동(README "화면 이동") → 필요하면 `details` 열기 → `__cap('before-<케이스>')`, `__cap('after-<케이스>')`.
- 캡처 결과로 돌려받은 `innerText`(또는 걸리는 요소 글자)를 보고 **맞는 화면을 떴는지** 확인한다. Vite가 사전·CSS 변경으로 페이지를 다시 불러오면 홈 화면을 뜰 수 있다.
- 영어 비교는 계정 언어와 `localStorage.language`를 같이 바꾼다.
- 인쇄 전용 시트는 `__capPrint`로 뜬다(README "인쇄본 비교").
- 숫자로 말할 수 있으면 잰다: 같은 캡처를 `DOMParser`로 읽어 바뀐 칸의 글자 수, 영어 모드의 한글 글자 수 등. 리포트 맨 위 요약표에 쓴다.
- 챗봇·서버 프롬프트가 바뀌면 AI를 부르지 말고, 두 브랜치의 프롬프트 생성 함수(예: `aiClient.buildSystemPrompt`)를 같은 진단 결과로 불러 **늘어난 줄**만 비교해 리포트에 싣는다.
- 실제 AI를 부르는 버튼은 누르지 않는다.

## 4. 리포트를 만들고 검증한다

- CSS: 브랜치마다 `scope-css.js`(폰), 인쇄본이 있으면 `print-css.js`(종이).
- 템플릿은 `template.example.html`을 본뜬다. 구성:
  1. 제목(무엇을 바꾸는지 이름으로)과 한 줄 설명: 어느 브랜치와 어느 브랜치를, 같은 서버·계정·과목으로 떴는지.
  2. "무엇이 바뀌고 무엇이 그대로인가": 바뀌지 않는 것(숫자·판정 등)을 먼저 굵게, 그다음 바뀌는 것 3~4줄, 숫자 요약표.
  3. 케이스마다 "지금 / 바꾼 뒤" 폰 두 대 + `data-pins` 번호 + 번호별 변화 목록(무엇이 어떻게 바뀌는지, 바뀐 문구는 그대로 인용). 같은 캡처의 다른 위치는 `data-scroll-to`로 보여 준다.
  4. 인쇄본(종이), 챗봇 프롬프트 차이 등 화면 밖 변화.
  5. "시안에서 하지 않은 것": 덜 구현한 범위, 임시 처리, 테스트 데이터 때문에 붙은 표시, 확인하지 못한 것.
  6. 바닥글에 검증 결과(아래 숫자).
- `build.js`로 묶고, 3010의 `report.local.html`을 모바일 탭에서 열어 `verify.js`를 돌린다. **폰 화면이 모두 0px 차이**여야 한다. 차이가 남으면 원인을 찾고, 못 없애면 리포트에 적는다. 같은 자리에서 `[data-pin]` 수가 `data-pins` 수와 같은지, 페이지가 가로로 넘치지 않는지도 본다.
- 게시 전 한 번만 화면을 본다(artifact-design 스킬 규칙). 고칠 것이 있으면 한 번 고치고 게시한다.
- `report.html`(`.local.html` 말고)을 알아보기 쉬운 이름으로 복사해 Artifact로 게시한다. 비공개 링크라 다른 사람에게 보여 주려면 공유해야 한다고 알린다.

## 5. 정리한다(빠뜨리지 않는다)

1. `test-state.js ... restore`로 테스트 계정을 되돌리고, 과목 수·학적이 원래대로인지 조회해 확인한다.
2. `preview_stop`으로 띄운 서버를 모두 끈다.
3. worktree: **junction을 먼저 끊고**(`cmd //c "rmdir ..\\wku-before-preview\\node_modules"`) 프로젝트 `node_modules`가 남아 있는지 본 뒤 `git worktree remove`.
4. `.claude/launch.json`을 되돌린다.
5. 시안 코드는 시안 브랜치에 커밋하지 않은 채로 둔다(사용자가 진행을 정하면 이어서 본 작업). 사용자에게 브랜치 이름과 상태를 알린다.

## 사용자에게 보고할 것

- 리포트 링크, 비교한 두 브랜치, 케이스 목록, 검증 결과(폰 N개 0px 일치, 인쇄본은 대조 밖).
- 화면을 뜨다가 새로 발견한 문제(예: 모든 학생에게 보이던 줄)는 따로 짚는다.
- 시안에서 하지 않은 것과 정리 상태(계정 복구, worktree·launch.json, 시안 브랜치 미커밋).
- 다음 결정 하나를 묻는다(예: 이 방향으로 진행할지).
